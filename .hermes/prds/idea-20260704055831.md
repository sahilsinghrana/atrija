# PRD: Bioluminescent Mushroom Glow

> **ID:** idea-20260704055831
> **Category:** Visual Enhancement
> **Priority:** medium
> **Status:** backlog
> **PRD Version:** 1.0
> **Last Updated:** 2026-07-04

## 1. Overview
Add subtle bioluminescent mushrooms scattered in the grass that pulse with a soft greenish light, enhancing the magical nighttime atmosphere without impacting performance.

## 2. User Stories
- As a user, I want to discover new magical elements in the scene so that my experience feels fresh and engaging.
- As a user concerned about battery life, I want the app to automatically optimize performance when my battery is low so that I can use it longer.
- As a user who enjoys interactive elements, I want to collect and release fireflies so that I feel a sense of agency in the environment.

## 3. Technical Specification
- Implement using existing Three.js scene or HTML5 Canvas overlay as appropriate
- Use Battery Status API when available, with fallback to viewport visibility heuristics
- Add event listeners for touch/click and keyboard interactions where applicable
- Ensure all additions are optional and can be disabled via configuration
- Follow existing code patterns in src/js/ for module structure
- For audio, use Web Audio API with fallback to HTML5 Audio

## 4. Test Plan (TDD)
1. Unit test: Verify mushroom particle system initializes with correct count and placement
2. Integration test: Check that mushrooms render correctly and pulse with appropriate timing
3. Performance test: Ensure mushroom animation adds <2ms frame overhead on mid-range devices
4. Visual regression: Compare screenshots to confirm mushrooms are visible but subtle
5. Acceptance criteria: Mushrooms should emit soft green light (rgba(0,255,0,0.3)), pulse every 3-5 seconds, and be distributed in clusters near tree bases

## 5. Acceptance Criteria
- Feature is visible and functional without reducing scene FPS below 30fps on Snapdragon 865 equivalent
- Battery saver activates when device battery <20% (simulated or real)
- Interactive elements respond to touch/click with appropriate visual and audio feedback
- No console errors or warnings introduced
- All new code follows existing ESLint and formatting rules
- Feature degrades gracefully when APIs are not available

## 6. Dependencies & Risks
- Dependencies: None (uses existing Three.js and standard web APIs)
- Risks: 
  - Battery Status API not available in all browsers -> mitigated by fallback to visibility heuristics
  - Interactive elements might interfere with existing controls -> mitigated by using non-obtrusive positioning
  - Audio might be blocked by autoplay policies -> mitigated by requiring user interaction first
